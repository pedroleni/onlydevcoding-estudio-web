## Resumen ejecutivo

La exclusión de `/grabar` del Proxy está bien cubierta. El Route Handler
exige por sí mismo el `Host` exacto `127.0.0.1:3000` y el `Origin` exacto
`http://127.0.0.1:3000` antes de leer los parámetros o el cuerpo, valida la
ruta con regex cerradas, exige `Content-Length` numérico entre 1 byte y
200 MiB, rechaza `Transfer-Encoding` y cualquier tipo distinto de
`audio/wav`, y reenvía a la API con cabeceras construidas desde cero: el
token sale de `process.env` y nunca de la petición. Contra una build de
producción y una API falsa, solo el par canónico llegó a escribir. El
`matcher` excluye únicamente `/grabar` y `/grabar/…`, y en esa ruta no hay
ninguna página ni Server Action que ejecutar: las variantes con mayúsculas,
codificación o `..` siguen pasando por el Proxy o acaban en el 404 estático.

Las dos Server Actions nuevas validan cada argumento, comprueban `Host` y
`Origin` con `headers()` y reconstruyen el cuerpo. El token no está en el
bundle y todos los textos de la API se pintan con JSX.

Queda un hallazgo MEDIUM: el panel de la vista previa enseña tal cual el
`error` del último trabajo, y la API puede componerlo con rutas absolutas del
disco. Hay además dos observaciones de endurecimiento que no puntúan.

## Hallazgos

# Vuln 1 (M1): Rutas locales en el error de la vista previa: `src/components/teleprompter/PanelPrevia.tsx:32-35` y `:96`

- Severity: Medium
- Description: `fallo` toma `trabajo.error` cuando el trabajo acaba en
  `error` o `interrumpido`, y se pinta como `Falló la última vez (${fallo}).`.
  El trabajo llega de dos sitios: `previa.trabajo` en la carga de
  `/teleprompter` y `leerTrabajo` cada 2 s desde el navegador. En la API,
  `trabajos.py` compone ese texto con la excepción: `No se pudo iniciar el
  trabajo: {exc}` si falla `Popen` y `No se pudo completar el trabajo: {exc}`
  ante cualquier otro fallo, incluido el `os.replace` del temporal al destino.
  Los `OSError` de Python incluyen las rutas absolutas. Se comprobó que un
  `cwd` inexistente da `[Errno 2] No such file or directory: '<cwd>'` y que
  `os.replace` da `'<temporal>' -> '<destino>'`. Con una API falsa que
  devolvía ese texto con una ruta ficticia, el HTML de
  `/teleprompter?curso=demo&leccion=1` contenía `Falló la última vez (No se
  pudo completar el trabajo: [Errno 2] No such file or directory:
  '/ruta/ficticia/tmp.mp4' -> '/ruta/ficticia/previa.mp4').` El texto va
  escapado, así que no hay XSS. El problema es el dato: la ruta incluye el
  directorio personal y la estructura de carpetas del estudio, que
  `AGENTS.md` prohíbe publicar, y los precedentes clasifican como MEDIUM o
  HIGH mostrar errores con rutas locales.
- Exploit Scenario: reproducción mínima. Arranca la API con un `ESTUDIO_DIR`
  que no exista o con una previa cuyo temporal no aparezca, y pulsa «Generar
  vista previa» en el teleprompter. Al terminar el trabajo, el panel muestra
  la ruta absoluta. El teleprompter es la pantalla que se tiene delante al
  grabar, y sus capturas acaban en PR, README o vídeos de un repositorio
  público. No hace falta un atacante: basta un fallo y una captura.
- Recommendation: no pintes `trabajo.error` en `PanelPrevia`. Usa un texto
  fijo («Falló la última vez.») y, si interesa distinguir casos, una lista
  cerrada según `trabajo.estado`. En la API, guarda en `error` un mensaje
  fijo y deja la excepción solo en el log del servidor. `Trabajo.registro`
  (las líneas de Remotion) también llega al navegador en la carga RSC y en
  `leerTrabajo`, aunque hoy no se pinta. No lo pintes sin filtrarlo. Añade un
  test de `PanelPrevia` con un `error` que contenga una ruta y comprueba que
  no aparece.

## Observaciones sin puntuar

# Obs 1 (O1): Versión sin codificar en la URL de la toma: `src/components/teleprompter/Teleprompter.tsx:475` y `:477`

- Severity: Informativo
- Description: la URL de la toma se construye como
  `${urlMedio(ruta)}&v=${tomaLocal.version}` y
  `&v=${escena.version_toma}`, sin `encodeURIComponent`, al contrario que
  `PanelPrevia`, que sí codifica la versión. Con una API falsa que devolvía
  `version_toma: "1&ruta=otra"`, el `src` del audio quedó
  `/api/medios?ruta=demo%2FE01.wav&v=1&ruta=otra`. Starlette se queda con el
  último valor repetido, así que la API serviría la segunda `ruta`.
- Exploit Scenario: ninguno realista hoy. La URL sigue apuntando a
  `/api/medios` de la API configurada, que contiene `ruta` en sus raíces, y
  la API tipa `version_toma` y `TomaGuardada.version` como `int`. Solo
  importaría si la API dejara de validar esos campos.
- Recommendation: codifica la versión igual que en `PanelPrevia`
  (`encodeURIComponent(String(version))`), o mejor, extrae `urlToma(ruta,
  version)` en `medios.ts` y úsala en los tres sitios.

# Obs 2 (O2): El `matcher` excluye todo el prefijo `/grabar`: `src/proxy.ts:53` y `src/proxy.test.ts:94-108`

- Severity: Informativo
- Description: `/((?!_next(?:/|$)|grabar(?:/|$)).*)` deja sin Proxy
  cualquier ruta que empiece por `/grabar`, no solo
  `/grabar/[curso]/[numero]/[escena]`. Hoy es inocuo: es la única ruta bajo
  ese prefijo, el resto da el 404 estático, y el Route Handler se protege
  solo. Pero una página o un handler que se añada más adelante bajo `/grabar`
  quedaría sin la validación de `Host` y `Origin`, y sin aviso: el test solo
  comprueba que `/grabar/react/4/E03` no pasa por el Proxy.
- Exploit Scenario: ninguno con el código actual.
- Recommendation: añade al test un caso que fije que el Proxy sí corre en
  `/grabarx`, `/Grabar/x` y `/grabar-algo`, y un comentario en `proxy.ts` que
  explique que todo lo que cuelgue de `/grabar` tiene que validar `Host` y
  `Origin` por sí mismo. Otra opción es estrechar el `matcher` al patrón
  exacto de la ruta (`grabar/[^/]+/[^/]+/[^/]+$`).

## Verificado sin hallazgos

- **Escáneres**: `scan_code_patterns.sh`, `scan_configs.sh`,
  `scan_dependencies.sh`, `scan_prompt_injection.sh` y `scan_secrets.sh`
  terminan con 0 hallazgos y código de salida 0. `test_scan_configs.sh` y
  `test_scanners_cobertura.sh` pasan. La batería de Vitest pasa en una copia
  de la rama (495 de 495).
- **Route Handler `PUT /grabar/[curso]/[numero]/[escena]`** (build de
  producción con `next start` en un puerto de pruebas, `Host` canónico
  enviado a mano, una API falsa que registraba cada petición y ningún dato
  real; además, peticiones que no escriben contra el `next start` del puerto
  3000):
  - `Host` y `Origin` canónicos con un WAV: la API recibe el `PUT` con el
    token, `Content-Type: audio/wav` y el mismo `Content-Length` y número de
    bytes (control positivo). El `detail` de un 422 de la API llega tal cual,
    y la API solo devuelve literales fijos en esa ruta.
  - Sin `Origin`, `Origin: null`, `Origin` ajeno, `http://localhost:3000`,
    `http://127.0.0.1:3000/` con barra final, dos cabeceras `Origin`, DNS
    rebinding (`Host` y `Origin` del atacante) y `Host: localhost:3000`: 403
    y ninguna petición a la API.
  - `Sec-Fetch-Site`: el handler no lo lee, y no hace falta. Los navegadores
    envían siempre `Origin` en un `PUT` y no dejan falsificarlo. Una petición
    redirigida desde otro sitio llega con `Origin: null`, y una página de
    `127.0.0.1:8000` llega con su propio origen. En ambos casos el handler
    responde 403. `X-Forwarded-Host` no cambia nada, porque se compara `Host`.
  - Un `X-Estudio-Token` enviado por el cliente no se reenvía: la API recibió
    el token del servidor.
  - Validación previa a la API: escena `E1`, curso `..%2f..%2fx` y número
    `01` dan 400; sin `Content-Type` o con `text/plain`, 415;
    `Transfer-Encoding: chunked`, 411; `Content-Length: 0`, 400; y
    `Content-Length` de diez dígitos, 413 sin esperar al cuerpo. Un
    `Content-Length` mayor o menor que el cuerpo real corta la conexión con
    400 y no llega nada a la API.
  - `GET`, `POST` y `DELETE` dan 405. `OPTIONS` da 204 sin cabeceras CORS,
    así que el preflight de otro origen falla.
  - La respuesta solo copia el `Content-Type` de la API: no reenvía cookies ni
    otras cabeceras. Un fallo de conexión da un 502 con mensaje fijo.
- **`matcher` del Proxy**: con `Host` ajeno, `/teleprompter`, `/cursos`,
  `/Grabar/x`, `/%67rabar/x`, `/grabar%2Fx`, `/grabar%2f..%2fteleprompter`,
  `/grabar/../teleprompter`, `/grabar/%2e%2e/cursos`,
  `/grabar;/../teleprompter`, `/./grabar/../cursos` y `/_next/%2e%2e/cursos`
  dan el 400 del Proxy. `/grabar`, `/grabar/x`, `/grabar/..%2fteleprompter` y
  la petición RSC a `/grabar/x` sirven el 404 estático (layout sin lecturas
  de la API y `not-found.tsx`). `/grabar//teleprompter` redirige a
  `/grabar/teleprompter`, que también es un 404.
- **Server Actions fuera del Proxy**: `generarPreviaGrabacion` y
  `guardarTextos`, lanzadas en `/grabar/x` (404) y en
  `/grabar/demo/1/E01` (405) con DNS rebinding e incluso con `Host` y `Origin`
  canónicos, no se ejecutan y la API no registra nada. Además, todas las
  Server Actions del proyecto comprueban `Host` y `Origin` con `headers()`
  (`ejecutar` de `acciones.ts` y `acciones-tareas.ts`, `origenPermitido` de
  `acciones-teleprompter.ts`, `opcionesLecciones` y `opcionesPiezas`), así
  que la exclusión no las dejaría expuestas aunque se registrasen bajo
  `/grabar`.
- **`guardarTextos` y `generarPreviaGrabacion`**: en `/teleprompter`, el DNS
  rebinding y un `Origin` ajeno dan el 403 del Proxy. Con origen canónico se
  rechazan sin llamar a la API: `numero` como cadena, `curso` con traversal,
  `version` que no es SHA-256 hex, un id de escena `../E01` y una frase con
  U+2028. Las escenas se reconstruyen con `id`, `cues` y `puntos`, así que los
  campos extra y `__proto__` se descartan. Hay como mucho 200 escenas y 200
  frases de 1 a 1000 caracteres. `detalleDe` con `textoBruto: false` solo
  devuelve `detail` de 404, 409 y 422. En la API esos detalles son literales
  o contienen solo el id de escena validado. Los errores inesperados se
  registran solo con el nombre del tipo.
- **`leerTrabajo` desde el navegador**: el `id` tiene que ser un entero
  seguro positivo. La URL sale de `NEXT_PUBLIC_API_URL`, que es pública por
  diseño. La petición no lleva token, usa `cache: "no-store"`, y la API solo
  permite CORS a `GET` desde el origen de la web. El error incluye solo el
  código de estado.
- **Token**: se ejecutó `next build` en una copia con `ESTUDIO_TOKEN` canario,
  sin leer `.env` ni `.env.local`. El valor no aparece en ningún archivo de
  `.next/`, y `.next/static` no contiene `ESTUDIO_TOKEN`, `X-Estudio-Token`,

- **Preferencias en `localStorage`**: `normalizarPreferencias` acota `ritmo`
