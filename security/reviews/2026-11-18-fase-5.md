## Resumen ejecutivo

Las dos Server Actions nuevas siguen el patrón aprobado: validan cada
argumento con listas o regex cerradas antes de tocar la red, comprueban `Host`
y `Origin` exactos con `headers()`, reconstruyen el cuerpo desde cero y
llaman a la API solo mediante `escribir` (`server-only`), así que el token no
sale del servidor. La acción va en la ruta solo si está en el catálogo, y
`previa` y `short` pasan por regex que impiden barras, puntos y saltos; la API
vuelve a exigir que existan en la lección. Los mensajes de error que llegan al
navegador son literales de la web o `detail` de cadena en 404, 409, 422 y 503,
y en la API todos esos `detail` son literales.

La ampliación de `guardarTextos` mantiene el mismo rigor para los ganchos: id
con regex, texto de 1 a 1000 caracteres sin controles ni separadores de línea,
como mucho 20, y nada de claves extra. Quitar el mínimo de una escena solo
admite una lista vacía cuando llegan ganchos.

Las cuatro copias de la comprobación de origen son equivalentes y comparten
las constantes de `origen-estudio.ts`; no hay divergencias peligrosas. Todos
los textos de la API se pintan con JSX, los enlaces y las URL de medios se
codifican y el sondeo solo pide un id entero mientras la pestaña está visible.
Las lecturas que degradan a `null` fallan cerradas: sin datos no aparecen ni
botones de editar ni acciones, y el error no se enseña.

## Observaciones sin puntuar

# Obs 1 (O1): Error del trabajo sin filtrar en las acciones: `src/components/acciones/BotonAccion.tsx:32-36`

- Severity: Informativo
- Description: `EstadoTrabajo` pinta `Falló: ${trabajo.error ?? "error
  desconocido"}` cuando el trabajo acaba en `error`. Es el mismo campo que
  motivó M1 en la fase 4. Aquel hallazgo se cerró por dos lados: la API dejó
  de componer `error` con la excepción (ahora solo guarda literales de
  `Mensajes`, `ERROR_CANCELADO`, `ERROR_INTERRUMPIDO` y `ERROR_SIN_PISAR`, y
  el único dato variable es el código de salida), y `PanelPrevia.textoFallo`
  descarta además cualquier texto con `/` o `\`. `BotonAccion` no aplica ese
  segundo filtro, y aparece en más sitios que el teleprompter: el aviso del
  montaje, las grabaciones de voz, el vídeo final y cada short.
- Exploit Scenario: ninguno con la API actual. Las filas antiguas tampoco lo
  abren hoy: la versión de la API que componía `error` con rutas solo vivió
  unas horas dentro de la rama de la fase 4, la migración v3 → v4 no reescribe
  `error`, y la base por defecto de la API no tiene ningún trabajo (consulta
  de solo lectura con recuento, sin leer contenido). Solo importaría si una
  versión futura de la API volviera a incluir la excepción.
- Recommendation: extrae el filtro de `PanelPrevia` a una función común (por
  ejemplo `textoErrorTrabajo` en `src/lib/`) y úsala en `BotonAccion` y
  `PanelPrevia`, con un test que pase un `error` con una ruta y compruebe que
  no se pinta.

# Obs 2 (O2): Comprobación de origen copiada y sin test en la acción nueva: `src/lib/acciones-estudio.ts:73-79` y `src/lib/acciones-estudio.test.ts`

- Severity: Informativo
- Description: `origenPermitido` está repetida en `acciones-estudio.ts:73`,
  `acciones-teleprompter.ts:122`, `acciones-tareas.ts:129` y, en forma
  negada, en `ejecutar` de `acciones.ts:138`, además de en el Route Handler
  `grabar/.../route.ts:23` con `request.headers`. Las cinco versiones son
  equivalentes: comparan `host` y `origin` con igualdad estricta contra
  `HOST_ESTUDIO` y `ORIGEN_ESTUDIO` de `origen-estudio.ts`, y en todas las
  Server Actions la comprobación va antes de la primera escritura. No hay
  divergencias peligrosas. Pero `acciones-estudio.test.ts` no tiene un caso de
  origen ajeno, mientras que `acciones-teleprompter.test.ts:241` sí lo tiene:
  si alguien borrara o invirtiera la llamada en `lanzarAccion` o
  `cancelarTrabajo`, la batería seguiría en verde. El Proxy seguiría
  protegiendo esas rutas, así que hoy no es explotable.
- Exploit Scenario: ninguno con el código actual.
- Recommendation: mueve la comprobación a un módulo `server-only` común (por
  ejemplo `origenPermitido()` en `src/lib/origen-servidor.ts`) y úsalo en las
  cuatro Server Actions, y añade a `acciones-estudio.test.ts` un caso por
  función con `Host` u `Origin` ajenos que compruebe `Origen no permitido` y
  que `escribir` no se llama.

# Obs 3 (O3): Lectura opcional que se traga cualquier error: `src/app/cursos/[curso]/[numero]/page.tsx:282` y `:285`

- Severity: Informativo
- Description: el teleprompter se lee con `lecturaApiOpcional` (línea 206),
  que solo convierte en `null` `ApiNoDisponible` y `ErrorApi` y relanza el
  resto. Las acciones se leen con `.catch(() => null)`, que convierte en
  `null` cualquier excepción, incluido un fallo de programación. En los dos
  casos el resultado es seguro: con `teleprompter` a `null` no aparecen los
  botones de editar ni los ganchos, y con `acciones` a `null` no aparece
  ningún `BotonAccion`, así que nada se habilita por error y el detalle no se
  enseña ni se registra. El `curso` ya está validado con `CURSO_VALIDO` en la
  línea 227 antes de las dos lecturas.
- Exploit Scenario: ninguno. Es una inconsistencia que puede ocultar un fallo
  real sin dejar rastro.
- Recommendation: usa `lecturaApiOpcional(obtenerAcciones(curso, numero))` en
  las dos llamadas para tratar igual las dos lecturas opcionales.

## Verificado sin hallazgos

- **Escáneres**: `scan_code_patterns.sh`, `scan_configs.sh`,
  `scan_dependencies.sh`, `scan_prompt_injection.sh` y `scan_secrets.sh`
  terminan con 0 hallazgos y código de salida 0. `test_scan_configs.sh` y
  `test_scanners_cobertura.sh` pasan. `npx vitest --run` pasa en la rama
  (55 archivos, 595 de 595) y `npm run lint` termina sin errores.
- **Sonda de las Server Actions** (Vitest con una configuración y un archivo
  temporales fuera del repositorio, mocks de `next/headers`, `next/cache` y
  `api-escritura`; 36 de 36 casos):
  - `lanzarAccion`, `cancelarTrabajo` y `guardarTextos` responden `Origen no
    permitido` sin llamar a la API sin `Origin`, con `Origin: null`, con
    `localhost:3000`, con DNS rebinding (`Host` y `Origin` del atacante), con
    `Origin` con barra final y con dos orígenes en la misma cabecera.
  - `lanzarAccion` rechaza antes de escribir: curso con traversal o
    mayúsculas, número como cadena, 0 o decimal, acción `__proto__` o
    `../../trabajos/1/cancelar`, opciones `null` o array, `previa` con `../` o
    salto de línea, y `short` con barra o numérico. Con claves extra y un
    `__proto__` en las opciones, el cuerpo enviado es solo
    `{ previa: "previa-v2.mp4" }`.
  - `cancelarTrabajo` rechaza 0, negativos, decimales, `NaN`, cadenas y
    enteros por encima de `Number.MAX_SAFE_INTEGER`, y envía un cuerpo vacío.
  - Mensajes: un `detail` que no es cadena en un 422, un `detail` en un 500,
    un texto bruto en un 503 y una excepción de red con una ruta dan siempre
    el literal de la web. Los errores inesperados se registran solo con el
    nombre del tipo.
  - `guardarTextos` con ganchos rechaza un id `../x`, textos con U+2028, NUL,
    solo espacios o 1001 caracteres, un gancho `null`, un objeto con aspecto
    de array y una lista vacía. Un gancho con `titulo` y `__proto__` se
    reenvía solo con `id` y `texto` recortado.
- **Lado de la API**: `OpcionesAccion` usa `extra="forbid"`; `previa` tiene
  que estar entre las previas de la lección y `short` tiene que cumplir
  `PATRON_ID_SHORT` y existir; los ganchos tienen que ser exactamente los del
  guion, sin repetir. Los `detail` de 404, 409, 422 y 503 de
  `rutas_acciones.py`, `acciones.py` y `seguridad.py` son literales o solo
  interpolan `node`/`npx`. El modelo `Trabajo` ya no incluye `registro`, así
  que las líneas de Remotion no llegan al navegador.
- **Token**: `acciones-estudio.ts` solo importa `escribir` de
  `api-escritura.ts` (`server-only`). Ningún componente cliente nuevo importa
  `api.ts` ni `api-escritura.ts`: los clientes solo importan las Server
  Actions (que el cliente recibe como referencias) y `trabajos.ts`, que usa
  `NEXT_PUBLIC_API_URL` sin token. El diff no añade variables `NEXT_PUBLIC_*`.
- **Server Actions y Proxy**: las acciones se invocan desde `/cursos/...` y
  `/trabajos`, dentro del `matcher`, así que el Proxy exige `Host` y `Origin`
  exactos antes que la propia función. Un formulario de otro sitio llega con
  su `Origin` y se rechaza. Los módulos `"use server"` solo exportan funciones
  asíncronas y tipos.
- **Renderizado**: no hay `dangerouslySetInnerHTML` ni `innerHTML`. Motivos,
  etiquetas, ids de escena sin alinear, ids de short, nombres de previa,
  títulos y textos de ganchos, `objetivo` y errores se pintan como texto JSX.
  `window.confirm` recibe un texto, y el único dato de la API que entra en él
  es el nombre de la previa elegida de la lista de opciones.
- **URLs y navegación**: el enlace de `/trabajos` es
  `/cursos/${encodeURIComponent(curso)}/${numero}` y siempre empieza por
  `/cursos/`, así que no admite `javascript:` ni otro host. `GrabacionesVoz`
  usa `urlToma`, que codifica la ruta y la versión, con `preload="none"`. Las
  rutas hacia la API de las Server Actions codifican `curso` y solo
  interpolan un número entero y una acción del catálogo.
- **Sondeo**: `useSeguimientoTrabajo` pide `leerTrabajo(id)` cada 2 s solo
  con un id entero seguro positivo, solo mientras el trabajo está `en_marcha`
  y la pestaña es visible, una petición cada vez, y se detiene al desmontar.
  `leerTrabajo` usa `cache: "no-store"` y su error solo incluye el código de
  estado. Al terminar refresca la página una vez.
- **Lecturas del servidor**: `obtenerAcciones` y `obtenerTrabajos` usan
  `pedir`, con `cache: "no-store"` y la URL de `API_URL`. `obtenerTrabajos`
  acota `limite` de 1 a 100 y lo pasa por `URLSearchParams`. `/trabajos` solo
  enseña el aviso genérico de `AvisoApi` si la API falla.
- **Datos hacia el cliente**: el `Teleprompter` completo viaja al componente
  cliente `GuionEditable` en la carga RSC. Son datos de la propia lección,
  servidos solo en `127.0.0.1:3000`, y sus rutas son las relativas públicas
  que ya revisó la fase 4.
- **Cadena de suministro**: `package.json` y `package-lock.json` no cambian.
- **Infraestructura**: no hay cambios en `.github/`, `next.config.ts`,
  `src/proxy.ts` ni en los scripts de `package.json`.
- **Entorno de agentes y prompt injection**: la rama no toca `.claude/`,
  `AGENTS.md`, `CLAUDE.md`, hooks ni scripts. El escáner no encuentra
  caracteres ocultos.
- **Historial y repositorio público**: el diff y los seis commits no
  contienen rutas absolutas, emails, tokens ni textos reales de lecciones. Los
  datos de los tests son ficticios («Lección ficticia», «Primera frase
  ficticia», «Gancho ficticio»). Los seis commits usan la dirección `noreply`

- **Estado de la fase 4**: M1, O1 y O2 están aplicados en `main`. La API
